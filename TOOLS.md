# Tools index

Every skill, tool and MCP server used with this repository: what each one is for and how it works.

_Generated by `python3 tools/build_tools_index.py` from the skill files and the catalog in that script. Do not edit by hand. Versions are the source versions in this checkout; installed versions per harness are in the local companion file `private-artifacts/TOOLS_LOCAL.md`, which is not published._

## Skills

Each skill is a folder under `skills/` with a `SKILL.md` (when it triggers, and the instructions) and a `README.md`.

|---|---|---|---|---|

### How each skill works

**[`boss-hunt-research`](skills/boss-hunt-research/README.md)**
- Each candidate route carries its evidence and a check that the information is still current.
- Never drafts or sends outreach.
- Includes a consistency validator and a privacy gate that runs before anything is published.

**[`calibre`](skills/calibre/README.md)**
- Keeps read-only commands separate from commands that change files.
- Never overwrites the input file and never touches a managed Calibre library.
- `scripts/calibre-machine-setup.sh` prepares a machine for it. Run that script in your own terminal, not from an agent session.

**[`closingtime`](skills/closingtime/README.md)**
- Builds evidence from local files and the Tasks database, then drafts the session entry, index update, task changes and learning candidates together.
- Asks for one approval of the exact changes, writes them, and reads every one back before it reports.
- Shares its runtime with newbeginning. Both are built from `skills/_shared/` with `sync_runtime_copies.py`.

**[`evidence-research`](skills/evidence-research/README.md)**
- Reuses prior work first, then picks the smallest method that can answer the question.
- Checks decisive claims against their sources and keeps unknowns visible instead of smoothing them over.
- Stops at the stated bounds and says what it did not check.
- Hands multi-platform consolidation to research-triangulation and hiring-contact dossiers to boss-hunt-research.

**[`local-whisper-transcription`](skills/local-whisper-transcription/README.md)**
- Checks that the machine is ready before anything runs. A policy file you write fixes the model and the folders it may touch.
- Picks the audio channel by scored evidence, splits long audio into overlapping chunks, repairs difficult spans, and assembles TXT, SRT, JSON and Markdown with global timestamps.
- Never installs, downloads or uploads anything without approval.

**[`nate-update`](skills/nate-update/README.md)**
- A seven-stage pipeline: find new Substack posts, then download articles, transcripts and prompt kits through browser automation.
- Ingests the new material into Open Brain.
- Keeps a state file, so an interrupted run resumes where it stopped.
- Claude Code only.

**[`newbeginning`](skills/newbeginning/README.md)**
- Reads `project_index.md` and the last two entries of `project_session.md`, plus the project's top tasks from the Tasks database.
- Returns at most 250 words and one question (pick up, discuss a task, or focus elsewhere), then stops.
- Read-only. The one exception is rebuilding a missing index, and only after approval.
- Snapshots, hashes, task receipts and the word count run through `scripts/runtime_cli.py`, so the brief cites checked evidence.

**[`research-triangulation`](skills/research-triangulation/README.md)**
- Writes a prompt for each platform (Claude, Perplexity, Gemini, ChatGPT, Grok and others).
- Scores each report against a rubric.
- Consolidates the reports by where they agree and disagree, so you know which findings are well supported.

**[`sync-jobs`](skills/sync-jobs/README.md)**
- Accepts LinkedIn, employer, ATS and Indeed postings, or postings from an unfamiliar job board.
- Validates each posting before it is synced.
- Optional triage scores postings against a candidate profile you choose. Real profiles stay local; the package ships only a synthetic example.

Changes to any of these skills follow [`skills/STANDARDS.md`](skills/STANDARDS.md): a request record, the agent's own git worktree, tests written first, the gate, an independent review, owner approval, then `skillchange.py install`.

## Repository tools

| Tool | Where | What it does | How it works |
|---|---|---|---|
| skillchange.py | `skills/_contrib/skillchange.py` | Gate, installs and drift checks for every change to a skill in this repo. | Commands: `status` shows source and installed versions; `gate` runs the certification checks; `install` re-gates a certified commit, backs up the installed copy and installs into the Claude Code and Codex skill folders; `check-installed` reports drift; `lock`/`unlock` make the installed copies read-only or writable. Follow `skills/STANDARDS.md` when you use it. |
| Session-skill runtime | `skills/_shared/` | The single source for the code and references that newbeginning and closingtime share. | `runtime_cli.py` handles snapshots, receipts, approvals and checked writes. Edit only here, then run `sync_runtime_copies.py` to copy the files into both skills. Contract tests: `run_contract_tests.py`, `run_helper_tests.py`. |
| Skill evals | `skills/<skill>/evals/` | Structural regression checks for each skill: file shape, metadata, references. | Run `python3 skills/<skill>/evals/structural_eval.py`. Some skills also have behavioural fixtures or runtime evals in the same folder. |
| books-api | `tools/books-api/` | Read-only lookup of public book metadata from Open Library and Google Books, as an MCP server or from the command line. | `books_status`, `books_search` (ISBN, or title and author, up to 10 results) and `books_get_record`. Sends one request per call, caches responses for 24 hours and never merges records from different providers. The source exists only on branch `chore/books-api-source` until that branch is merged. Details: `tools/books-api/README.md`. |
| openrouter_spend.py | `tools/openrouter_spend.py` | Checks today's OpenRouter spend against the agent allowance, and logs each agent run. | Run with no arguments for the spend check. Exit 0 means allowance is left, 3 means it is used up, 2 means something failed. `--record ...` appends one run to the local run log. Never prints a key. |
| release.sh | `scripts/release.sh` | Publishes one skill as a release. | `./scripts/release.sh <skill> <version>` builds a `.skill` bundle, tags `<skill>-v<version>` and publishes a GitHub release. This is outward-facing, so it needs the owner's go-ahead. |
| calibre-machine-setup.sh | `scripts/calibre-machine-setup.sh` | Prepares a machine for the calibre skill. | Links Calibre's command-line tools onto PATH, adds a read-only permission allowlist and installs the skill. It is safe to run again. Run it in your own terminal, not from an agent session, because it changes permissions. |
| skill-doc-generator (patched) | `tooling/skill-doc-generator-patched/` | Generates and validates README files from SKILL.md files. | A fork of the stock skill-doc-generator with four bug fixes. Usage is in its `PATCH_NOTES.md`. |
| Tasks dashboard | `tasks-dashboard/` | A read-only web view of the Tasks database. Its first question is what is slipping. | A Next.js app that reads through a read-only gateway. Task changes still go through skills. Not yet tracked in git. Details: `tasks-dashboard/README.md`. |
| build_tools_index.py | `tools/build_tools_index.py` | Builds this index. | Run `python3 tools/build_tools_index.py` to rewrite this file and its local companion. `--check` exits 1 when this file is out of date. Descriptions live in the script's catalog; versions come from the skill files. |

## MCP servers

MCP (Model Context Protocol) servers give an agent extra tools. These are the servers the skills rely on.

| Server | What it is | Tools | How it works | Source |
|---|---|---|---|---|
| `tasks_mcp` | Gateway to the Tasks database, limited to tasks. It is the single source of truth for cross-project to-dos. | `urgency` (ranked open tasks for one project, or the whole portfolio), `list_tasks`, `get_task`, `create_task`, `update_task` | Read freely. Every write needs owner approval of the exact change and goes through the task-db or closingtime skill. Deletes, schema changes and view changes never go through agents. | Separate private project |
| `open-brain` | Personal knowledge store: captured thoughts and learnings, plus the Nate B. Jones archive. | `search_thoughts`, `list_thoughts`, `capture_thought`, `thought_stats`, `search_nate_content`, `nate_content_stats` | Search compares meaning, not just keywords. Captures happen during a session or at closingtime, and only after approval. | Separate private project |
| `kb-search` | Search over a reviewed personal reading knowledge base: notes on books, articles, talks and podcasts, plus their full sources. | `search`, `get_note`, `get_passage` | Runs locally only while a session needs it. Meaning search embeds the question with a local model; when that model is not running, search falls back to keywords and says so. | Separate private project |
| `books-api` | Public book metadata. See books-api under Repository tools. | `books_status`, `books_search`, `books_get_record` | Read-only, and runs locally over stdio. | This repo: `tools/books-api/` |

## Harnesses

A harness is the agent app that runs a model and loads these skills and servers.

| Harness | Skill folder | How skills get there |
|---|---|---|
| Claude Code | `~/.claude/skills` | Installed by `skillchange.py install`, locked, drift-checked. |
| Codex | `~/.codex/skills` | Installed by `skillchange.py install`, locked, drift-checked. |
| OpenCode | `~/.config/opencode/skills` | Copied by hand, with no drift check. OpenCode also loads `~/.claude/skills`; nate-update is hidden there by a permission rule. |
| Gemini | `~/.gemini/config/skills` | Copied by hand, with no drift check. Holds only some of the skills. |
| claude.ai | `uploaded zip` | Uploaded by hand. It can lag behind the installed version. |
