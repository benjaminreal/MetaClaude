# Transferability Statement

Candidate 1.2.9 is the release-hardening successor to the independently recertified
1.2.8 harness-install build. It preserves the research workflow, portable
Codex/Claude Code inventory classifier, provider-neutral Hunter operations,
external-Chrome/internal-browser selection, harness-aware installs, and explicit
`REVIEW_PENDING` ceiling. It adds an offline privacy/secret scan over the complete
publishable tree plus an optional Git-index completeness gate, and replaces
owner-local paths in public certification history with named portable roots. This
delta does not expand live, drafting, send, registration, or mutation authority.
The source, Codex install, and Claude install remain hash-certified separately;
installation parity is not claimed and no earlier certification transfers
retroactively.

For candidate 1.1.1, a competent external user can validate a canonical target, derive capability-specific stop/fallback states, generate the ordered plan, initialize a V3 dossier in a user-supplied isolated directory, capture and hash evidence, serialize current guard and currentness receipts, deduplicate hook intents, bind exact hook evidence, represent candidate proof and access limitations, enforce channel/Hunter budgets, run the portable structural-first suite, and prepare/attach a separate hash-bound six-check review. Seven skill sections and seven onboarding sections were certified; an independent fresh-context cold handoff found four gaps, all patched and passed on rerun. A later portability review found an owner-machine validator path in Section 6; candidate 1.1.1 removed it, re-certified the affected documentation, and added a regression that rejects machine-specific paths in certified runtime docs.

Certification does not cover live evidence acquisition or truth, professional-profile authentication, Hunter execution, final inbox verification, drafting, owner approval, sending, tracker registration, outreach efficacy, production readiness, installation, or release. Those remain explicit external capability or authorization boundaries. Semantic source independence also remains a reviewer responsibility; two asserted URLs or keys do not prove independence.

The system is extensible through leaf-specific capabilities and evidence-bound contracts: any new source, connector method, route, or workflow branch must add a scoped receipt, fail-closed result, ordering/budget rule, structural contract, one-defect mutant, independent stress test, affected section re-certification, and updated handoff/onboarding boundary before it can join the certified scope.
