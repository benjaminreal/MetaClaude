# Evidence records

For a small answer, direct source citations with the necessary scope can be the
entire record. For reusable or extended work retain the fields that matter:

- question/claim ID and the actual statement;
- source ID, URL or local path and passage/page/row locator;
- publication, effective and capture dates when distinct and material;
- underlying origin/source family and real-world entity/observation identity;
- scope: entity, jurisdiction, period, population, geography and units;
- evidence type: source fact, inference, assumption or adopted decision;
- support: supported in stated scope, partially supported, unresolved or
  contradicted, with the reason and any contrary evidence;
- next evidence needed, including where a human/field check is required.

Use existing project schemas when appropriate; this is not a mandatory JSON
format. Preserve an exact quotation only as needed and permitted. Save a durable
source copy and hash when instability, reproducibility or the task warrants it.

Keep source-access state separate from claim support and decision approval.
A confirmed passage may support only a general rule; applicability can remain
unresolved. A model report can point to an underlying source without becoming
an extra independent observation. Audit the meaning, not merely whether a
quotation occurs in a file.

Never silently replace historical receipts. Link later corrections to the
current authoritative finding, retain prior captures and show their status.
A factually accurate answer may still fail if it does not answer the user's
question or hides uncertainty material to the decision.
